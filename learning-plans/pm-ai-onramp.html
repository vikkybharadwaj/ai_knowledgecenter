The one idea that organizes everything

Prompt → Context → Harness → Loop

Each era didn't replace the last — it wrapped it. The skill that creates value kept moving outward, from "write a clever ask" to "design a system that runs itself."

EraWhat you controlPlain-English versionThe PM analogy from your world
1. PromptOne ask, one answerHow you phrase a single requestA single, well-written ticket or brief
2. ContextWhat the model sees this turnInstructions, files, history in its working memory — incl. RAG (pulling in the right docs automatically)The data, specs & guardrails you put in front of a team before they start
3. HarnessThe gather → act → verify loopThe model in a cycle: uses tools, checks its own work, retries — not one replyAn experimentation system: hypothesis → run → measure → iterate. The measure step is the point.
4. LoopThe harness running itselfThe system kicks itself off, spawns helpers, works unattendedA standing program with its own cadence — a growth engine that runs without you in every meeting

And they nest.

┌─ LOOP — runs itself, on a cadence, spawns helpers ───────────┐ │ ┌─ HARNESS — gather → act → verify, tools + memory ──────┐ │ │ │ ┌─ CONTEXT — what's in the window (+ RAG) ────────┐ │ │ │ │ │ ┌─ PROMPT — the single ask ──────────┐ │ │ │ │ │ │ └─────────────────────────────────────┘ │ │ │ │ │ └──────────────────────────────────────────────────┘ │ │ │ └──────────────────────────────────────────────────────┘ │ └────────────────────────────────────────────────────────────┘

The instinct this gives you: "Which layer is this problem on?"

The single most useful reflex in an AI roadmap review. When something's wrong, the symptom tells you which layer to fix — and stops you from "just rewording the prompt" forever:

The symptomLayer that's actually brokenThe fix
"Bad answer, but a clearer ask fixes it"PromptReword. (You already do this.)
"It forgot what I told it / missed the relevant doc / drowning in irrelevant text"ContextCurate the window — Projects, instructions, RAG
"Plausible but wrong, and it didn't catch it"HarnessAdd verification, tools, a check step
"It works, but I babysit every step"LoopDesign the system that runs the steps
The big shift for a PM: "AI quality" is rarely a model problem. It's almost always a context or harness problem — i.e., a product design problem you're equipped to own. That's the opening.

Appendix A

The evolution, expanded (the connect-the-dots)

The four eras as a story of where the leverage moved:

Prompt engineering — Leverage = phrasing. You optimize a single turn. Real, but capped: the model only knows what's in front of it and gets one shot.

Context engineering — Leverage = curation. The model is only as good as its window, so you manage it: instructions, examples, and retrieval (RAG) to pull in the right knowledge at the right moment. Most "make the AI better" work is here.

Harness engineering — Leverage = the loop around the model. One reply isn't enough for real work, so you wrap the model in a cycle — gather → act → verify → retry — plus memory. Where reliability is won or lost. Key truth: the model is systematically overconfident, so "done" is judged by the harness, not the model (see Appendix C).

Loop engineering — Leverage = the system. You stop writing turns and design the thing that writes them: a harness that triggers itself, spawns sub-agents, runs unattended. A loop is just cron + a decision-maker — a scheduler running a model that decides what to do next, not a fixed script.

Why this matters to you: your edge isn't model internals — it's knowing which layer a problem lives on and designing the product around it.

Appendix F

Decision guide ("I want X → reach for Y")

"It to know my docs/specs."→ Context: a Project + uploads (RAG).
