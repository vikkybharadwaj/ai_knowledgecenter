The one idea that organizes everything

Claude Code is a harness wrapped around a language model. The model is the engine; everything with a name — CLAUDE.md, skills, hooks, MCP, subagents, teams, workflows — exists to control one of four things. Every feature you’re confused about is just an answer to “which of these four am I trying to change?”

① What it knows

The words and context fed in. Soft — guidance, not a guarantee.

CLAUDE.md · rules files · skills · output styles · effort

② What it can reach

The tools and external systems available to it.

built-in tools · MCP servers

③ What’s guaranteed

Things that happen regardless of the model’s choices. Hard enforcement.

hooks · permission rules · managed policies

④ How work is coordinated

Scaling from one prompt to hundreds of agents.

subagents · agent view · agent teams · workflows · worktrees

The two axes you’ll use all guide long Soft vs Hard: does the model choose to follow it (CLAUDE.md, skills) or does the client enforce it no matter what (hooks, policies)?  ·  Who holds the plan: you in one prompt → the model in one session → the model coordinating peers → a script. The further right, the more parallel and the less you watch each step.

Deep-dive cards

Conventions (CLAUDE.md / rules files)

Soft, persistent guidance the model reads every session.

 → 301 hard

Policies (managed settings + permission rules)

Client-enforced governance that the model can’t override. Not the same as conventions.

 → 201 hard

Hooks (vs “rules”)

Your code, run automatically on lifecycle events. Not the same as rules.

 → 201

Skills (& what “routines” really means)

Reusable instructions/procedures loaded on demand. “Routines” isn’t a real term — it’s this.

 → 201

A protocol that gives the model new tools & data from external systems.

 → 201
