Names blurring together — conventions vs policies, “routines,” rules vs hooks? → Terminology fixes.

→

Conventions (CLAUDE.md / rules files)

Soft, persistent guidance the model reads every session.

 → hard

Policies (managed settings + permission rules)

Client-enforced governance that the model can’t override. Not the same as conventions.

 → hard

Hooks (vs “rules”)

Your code, run automatically on lifecycle events. Not the same as rules.

 →

Skills (& what people mean by “a routine”)

Reusable instructions/procedures loaded on demand. A saved procedure you call “a routine” is this — not the new Routines feature (its own card below).

 →

MCP (Model Context Protocol)

A protocol that gives the model new tools & data from external systems.

 →

Subagents

Delegated workers in their own context; only a summary returns.

 → experimental

Agent teams

A lead + peer sessions that share a task list and message each other.

 → preview

Dynamic workflows (+ ultracode)

Claude writes an orchestration script that runs dozens-to-hundreds of agents.

 → preview

Worktrees + Agent view

Git isolation per session, plus one dashboard to dispatch & watch many of them.

 → research preview

Routines (unattended cloud automation)

A saved config that runs itself on Anthropic’s cloud — on a schedule, a GitHub event, or an API call.

 →

/loop (scheduled tasks)

Re-run a prompt on an interval inside an open session — cron syntax with a model deciding each tick. The in-session cousin of routines.

 →

/goal (work until a condition holds)

Keep working turn after turn until a fresh small model confirms a condition is met. Condition-driven, where /loop is clock-driven.
